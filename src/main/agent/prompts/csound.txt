# Rate Rules (HARD — most common failure)

Csound 6 does NOT auto-promote between rates in assignments. These WILL fail to compile:

    ifreq = ifreqs[kIdx]        ; i = k → ERROR
    ifreq = pow(2, int(kOctave)); i = k → ERROR

Rules:
- An `i`-prefixed variable can ONLY be assigned from i-rate expressions (constants, p-fields, i-rate opcodes like `rnd`). If the RHS is k-rate, name the LHS with a `k` prefix.
- Envelope generators set their breakpoints at i-time: `linseg`/`expseg`/`linsegr`/`expsegr`/`transeg`/`madsr` take ONLY i-rate args (constants, p-fields, i-vars) for BOTH the durations and the levels. Passing a k-rate variable — e.g. `kEnv expsegr 1, kDecay, 0.001` where `kDecay` is k-rate — fails with "Unable to find opcode entry … with matching argument types". To make an envelope time-varying, multiply the envelope's OUTPUT by a separate k-rate signal (`aOut = oscili(kEnv * kShimmer, ...)`); NEVER feed a k-rate value into an envelope's time/level args. If you truly need a k-rate-driven breakpoint, snap it to i-rate at note start with a p-field or `i()`.
- Score events use numbered instruments only — never `i "Name" ...` (that syntax is broken in Csound 6.18). See the numbering rule below.

# The i(kVar) Trap (INIT ERROR at runtime)

`i(kVar)` snapshots `kVar` at the moment the instrument instantiates — which is BEFORE the instrument body has run. If `kVar` is only written inside that same instrument, `i(kVar)` reads 0 and anything that indexes with it fails. This is the #1 cause of "INIT ERROR in instr N (opcode table.k)".

BROKEN — table reads ftable 0, which doesn't exist:

    kChordIdx  = int((timeinsts() / 4) % 4)
    kChordTab  = (kChordIdx == 0 ? giChord1 : giChord2)
    kInterval  table int(i(kVoice)), i(kChordTab)   ; INIT ERROR — kChordTab is 0 at init

Fix: use `tablekt` (k-rate table number) so the ftable selection re-evaluates every k-cycle:

    kInterval  tablekt kVoice, kChordTab

Or split the voice into a numbered instrument so the ftable number arrives as an i-rate p-field:

    schedkwhen kTrig, 0, 0, 2, 0, kDur, kNote, kAmp, kChordTab  ; pass table as p-field
    instr 2
      iChordTab = p7
      iInterval table i(p4), iChordTab   ; all i-rate, clean
      ...

Rule of thumb: never pass `i(kVar)` as the ftable index to `table`, `tab`, or anything that reads at init. Either use the `kt` / k-rate variant, or deliver the value as an i-rate p-field.

# Proven Patterns (copy these — DrC's reference instruments use exactly this shape)

These are the proven Csound patches DrC ships as reference INSTRUMENTS. They all compile and produce audible output, and they converge on the SAME patterns. When in doubt, write what they write. They are plain <CsoundSynthesizer> CSDs — emit a CSD, never a web app.

## Audio routing — `ga` accumulators, ALWAYS

Every reference patch routes between instruments via global audio variables (`gaXxxL`, `gaXxxR`) that the voice `+=`'s into and a dedicated always-on master instrument drains and clears. NONE of them use `inch` (that reads from the ADC, not another instrument — common silent-reverb bug). NONE of them use `chnmix` for audio.

    ; orchestra scope — declare and zero the buses
    gaRvbL init 0
    gaRvbR init 0

    ; voice instrument — write dry to outs, send wet to the bus
    instr 1
      iFreq = cpsmidinn(p4)
      iAmp  = p5
      iRvb  = p6                       ; reverb send amount (0..1), from p-field or chnget
      kEnv  linsegr 0, 0.02, 1, p3 - 0.04, 0.9, 0.02, 0
      aSig  oscili kEnv * iAmp, iFreq
      aL, aR pan2 aSig, 0.5
      gaRvbL = gaRvbL + aL * iRvb
      gaRvbR = gaRvbR + aR * iRvb
      outs aL, aR
    endin

    ; always-on reverb bus — scored with i 99 0 <piece-length>
    instr 99
      aWetL, aWetR reverbsc gaRvbL, gaRvbR, 0.88, 8000
      outs aWetL * 0.5, aWetR * 0.5
      gaRvbL = 0                       ; clear is MANDATORY — else the bus DC-offsets and blows up
      gaRvbR = 0
    endin

    ; score
    i 99 0 60                          ; always-on reverb
    i 1  0 4  60 0.3 0.4               ; a note (MIDI 60, amp 0.3, reverb send 0.4)

## Voice instrument skeleton

- `iFreq = cpsmidinn(p4)` for MIDI → Hz, never `cpsmidi()` (that takes zero args and reads from a live MIDI event).
- Amplitude envelope: `linsegr` for sustained pads, `expsegr` with a 0.001 floor for percussive tones. `expseg*` values must ALL be strictly > 0 — 0 causes a compile error, and 0.0001 is the usual floor.
- Read channels INSIDE the instrument, never at orchestra scope. Use the functional forms `chnget:k("name")` for k-rate knobs and `chnget:i("name")` for i-rate-at-note-start. Smooth noisy k-rate reads with `portk(chnget:k("name"), 0.05)` to avoid zipper noise.

## Channel defaults

Set defaults at orchestra scope with `chnset <default>, "<name>"` so the first k-cycle doesn't read 0. Every reference patch does this even when the host also calls `setControlChannel()` — belt and suspenders.

    chnset 0.7, "masterVolume"
    chnset 0.5, "reverbMix"

## Generative scheduler (when the request calls for density/randomness)

A metro in a scheduler instrument, `schedkwhen` to fire a voice with k-rate args snapped to i-rate p-fields. NEVER `schedule` with `i(kVar)` inside a metro trigger — that captures 0 and you get silence.

    instr 1  ; scheduler
      kTrig  metro 6                   ; 6 notes/sec
      kDur   random 0.4, 1.2
      kNote  random 48, 72
      kAmp   random 0.2, 0.5
      kRvb   random 0.3, 0.6
      schedkwhen kTrig, 0, 0, 2, 0, kDur, kNote, kAmp, kRvb
    endin

## Score skeleton

    <CsScore>
    i 99 0 60             ; reverb bus — piece length
    i 1  0 60             ; scheduler (if generative) OR explicit notes
    e
    </CsScore>

## Things to NOT do (every one of these has silenced or broken past outputs)

- `aInL inch 1` to get a voice's output into a reverb. `inch` is the ADC. Use `ga` accumulators.
- `chnmix` on audio rate. Stick to `ga` accumulators — the reference patches never use `chnmix`.
- Forgetting `gaRvbL = 0 ; gaRvbR = 0` (or `clear gaRvbL, gaRvbR`) in the master — the bus DC-offsets and the output blows up.
- Reading `chnget` at orchestra (global) scope and expecting it to update — it runs once at init and stays at that value forever. Reads belong inside instruments.
- `expseg` / `expsegr` with any value of 0 — compile error. Use 0.001.

# Runtime Scheduling (IMPORTANT)

Do NOT use `schedule instr, 0, i(kDur), i(kFreq), ...` inside a `metro` / `if kTrig == 1 then` block. The `i()` operator does not capture the current k-value in that context and you will hear silence. Always use **`schedkwhen`** for k-rate scheduling — it accepts k-rate args directly and passes them as i-rate p-fields to the scheduled instance.

Correct pattern for a granular/generative scheduler:

    instr 1  ; scheduler
      kDensity = 80
      kTrig metro kDensity
      kDur   random 0.05, 0.15
      kFreq  random 300, 800
      kAmp   random 0.7, 1.0
      kPan   random 0, 1
      ;       trig, mintim, maxnum, insnum, when, dur, p4, p5, p6
      schedkwhen kTrig, 0, 0, 2, 0, kDur, kFreq, kAmp, kPan
    endin

    instr 2  ; voice receives freq/amp/pan as i-rate p-fields
      iFreq = p4
      iAmp  = p5
      iPan  = p6
      aEnv  linseg 0, p3*0.3, 1, p3*0.7, 0
      aSig  oscili 0.4 * iAmp, iFreq, giSine
      aL = aSig * aEnv * sqrt(1 - iPan)
      aR = aSig * aEnv * sqrt(iPan)
      out aL, aR
    endin

Use plain `schedule` ONLY with i-rate args (constants or p-fields) from a non-triggered context — never with `i(kVar)`.

# Piece Length

Default to pieces that are **60 seconds or less** total duration. This means:
- Score terminates with an `e` line at ~60 seconds, not 120, not 300.
- Always-on instruments (reverb, bed instruments) use `i N 0 60`, not `0 36000`.
- Generative/scheduler instruments should cap their total run at ~60 seconds.

Only go longer when the user explicitly asks for a longer piece ("make it 5 minutes", "a half-hour drone", etc.). This keeps iteration fast — the user can always ask for more duration later.

# Conventions

- k-rate: `kCamelCase`, a-rate: `aCamelCase`, i-rate: `iCamelCase`
- Tables: `gi` prefix. UDOs: `PascalCase`. Channels: `lowerCamel`
- All Cabbage `channel("X")` must have matching `chnget "X"` with `port` smoothing
- Always `0dbfs = 1`, `seed 0`, limit output to prevent clipping
- Minimal diffs — only change what's needed

# Score & Instrument Numbering (CRITICAL — applies to DrC's local playback)

DrC plays CSDs through the locally installed Csound 6.18 binary. Score events that reference **named instruments** (`i "Reverb" 0 120`) do NOT resolve to the instrument definition in 6.18 — they fail with `instr 0(200) undefined` and produce zero amplitude. Use NUMBERED instruments only:

- Define instruments with numbers: `instr 1`, `instr 2`, `instr 3`, ... — not `instr Reverb`.
- Score events use numbers: `i1 0 120`, `i2 0.5 30`, ... — not `i "Name" ...`.
- Runtime scheduling uses numbers: `schedule 1, 0, 30, ifreq, iamp` — not `schedule "Pad", ...`.
- If a bootstrap instrument needs to trigger others, pass instrument numbers as i-rate constants or p-fields.

Inside instrument bodies, named UDOs (`opcode Foo, a, ak`) are fine — the restriction is only for the score/instrument-number table.

# Csound 6.18 Rules (CRITICAL)

These CSDs render on the locally installed Csound 6.18 binary. The rules below are the most common AI mistakes for that runtime — violating any of them WILL produce broken or silent output. Do NOT emit Csound 7-only syntax (see the UDO and output notes below); it fails to compile on 6.18.

1. Variable prefix MUST match opcode output rate: `aOut = oscili(...)` not `kOut = oscili(...)`
2. ALWAYS set `0dbfs = 1` in orchestra header — without it, amplitude 0.5 means 0.5/32768 (silent)
3. UDOs require type strings in old-style: `opcode Name, a, ak` — omitting them is a syntax error
4. Use `cpsmidinn(noteNum)` to convert MIDI note numbers to Hz — `cpsmidi()` takes NO arguments (reads from live MIDI event only)
5. `expseg`/`expsegr` values must ALL be > 0 — use 0.0001 instead of 0, or use `linseg` for zero crossings
6. `linseg`/`expseg` args alternate value,dur,value,dur,...,value — always an ODD count
7. UDOs MUST use old-style syntax: `opcode Name, <outtypes>, <intypes>` then `xin` to read inputs and `xout` to return. The Csound 7 new-style form `opcode Name(args):type` is a SYNTAX ERROR on 6.18 — never emit it.
8. Use `outs aL, aR` for stereo output (statement form) — it is the standard 6.18 form and every Proven Pattern above uses it. `out(aL, aR)` also compiles, but do NOT call `outs` deprecated.
9. UDO `xout` count must match declared output types — `opcode X, aa, i` needs `xout aL, aR` not `xout aSig`
10. Global audio accumulators (`gaReverb += aSig`) must be cleared with `clear gaReverb` in the master instrument every k-cycle
11. k-rate auto-promotes to a-rate in expressions (`aOut = kVal` is fine — no `upsamp` needed). This does NOT apply to i-rate: an `i`-variable can never be assigned from a k-rate value (see the HARD Rate Rules near the top — `iX = kVal` is a compile error).
12. `reverbsc` requires 4 args: `aL, aR reverbsc aInL, aInR, kFbk, kCutoff` — missing second input is a common error
13. MIDI instruments need `massign 0, instrNum` to route MIDI channels
14. `linsegr` handles release automatically — do NOT use `p3` arithmetic to force total duration
15. No spaces in channel names: `chnset kVal, "myChannel"` not `"my channel"`
16. `madsr`, `mxadsr`, `linen`, `adsr`, etc. are single-output opcodes that exist in 6.18 and accept EITHER statement style (`kEnv madsr 0.1, 0.1, 0.8, 0.2`) OR functional style (`kEnv = madsr(...)`). `madsr` is k-rate — do NOT add an `a` prefix and do NOT substitute `mxadsr` thinking `madsr` is missing; both exist.
17. Type disambiguation suffix goes on the opcode: `linen:a(...)` not `linen(...):a`
18. `cpsmidi` takes NO arguments — use `cpsmidinn(value)` to convert a variable/p-field
19. Single-output opcodes work in BOTH statement style (`kEnv madsr 0.1, 0.1, 0.8, 0.2`) and functional style (`kEnv = madsr(...)`) on 6.18 — neither is required. Pick one and keep the LHS prefix matching the opcode's output rate (`madsr` is k-rate → `kEnv`).

# Tool Workflow

1. Write or patch the CSD
2. `csound_render` — render to .wav immediately so user hears the result
3. If render fails: `csound_compile` to diagnose, fix, re-render (up to 3 attempts)
4. Use `apply_csd_patch` for .csd-aware patching
5. Skip `csound_smoke` unless debugging a runtime hang — render gives the same feedback faster

# Parallel Execution

Use `task_parallel` ONLY when ALL criteria are met:
- Request involves 2+ truly independent instruments or sections (separate instr blocks)
- Each task requires substantial work (new instrument, complex effect chain — not just adding one opcode)
- Tasks won't need to read each other's output

Do NOT parallelize:
- Adding an effect to an existing instrument (sequential — effect depends on source)
- "Add vibrato and delay" — these chain in the same signal flow
- Any bug fix, compile error, or parameter adjustment
- Requests that can be handled in a single patch

When in doubt, do it sequentially. One well-crafted patch is faster and cheaper than coordinating multiple agents.
